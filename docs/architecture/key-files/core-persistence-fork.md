- `src/core/persistence/rename-prepare.ts` — preparer for the `rename_page` op. The page row moves with `updateSlug` inside the journal publication transaction (the page id and everything keyed to it stay attached; `updateSlug` records the `old -> new` slug alias and moves slug-keyed facts, withdrawals and page_aliases), then the preparer reads the alias row back and refuses to commit without it, and reseals the text projection. The coordinator locks both page keys (the new slug via `additionalPageKeys`) and rechecks the old page's identity and revision; `validate` rechecks under that lock that the new slug holds no live page, no tombstone and no alias to another page (`slug_conflict`). Sources with a working tree (local_path, `sync.repo_path` for `default`, or a worktree binding) are refused with `source_writeback_required` / `detail: rename_requires_file_move` before admission and again at preparation, because a database-only rename would leave the old file to be re-imported. `authorizeStoredRequest` also authorizes the target slug, from the intent or the committed outcome. `updateSlug` is upstream's (0.60.543): it also keeps the move in `slug_rename_history` (v285) for folder-rule lineage. A `## Links` fence row in another page that names the old slug follows the alias when that page's fence is projected again (`links-fence-projection.ts`), so the manual edge is not dropped. Tests: `test/rename-page-op.test.ts`.
- `src/core/persistence/untiled-revert.ts` — revert_version as the repair of a segmented page whose live generation does not tile its body (every reader answers `page_body_rows_unreadable`; put_page and edit_page read the current body first, so they refuse too). `prepareUntiledRevert` runs before the preparation reads the stored body (page-prepare.ts) and returns null unless upstream's tiling test lists the page (`untiledSegmentedPages`, page-body/body-tiling.ts, over `liveTilingSql`/`untiledSql`: doctor `segmented_tiling`'s predicate), so an ordinary segmented revert keeps refusing with `segmentedRevertRefusal`. It streams a segmented version's body from that version's own generation (whose rows must tile the version's body_bytes; a version of the unreadable generation itself, an inline version, a core-marked page or version and a page with a canonical file refuse), stages it against the live page (`prepareSegmentedBody`), versions the page (a reference to the unreadable generation, kept as history), flips, sets the version's title, type, frontmatter and tags and reseals. It re-projects nothing: facts, takes, links and timeline rows keep their ids and states. No reader can return the page's revision, so callers pass `force: true`; the outcome carries `repaired` (the unreadable generation, its body_bytes and covered bytes, the version used). `repair segmented-tiling` is the Git-backed repair and refuses a repo-less source; this is the repair there. The version-before-flip ordering and the flip's tiling guard are upstream's (#8729, GST-1209).
