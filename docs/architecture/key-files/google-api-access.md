# Google connector account identity, API access and sender authentication (key files cluster)

[Subsystem index](../KEY_FILES.md) · [Google connector + open-loop engine](google-and-loops.md).

- `src/core/google/api-access.ts` — #7004/#7073 account identity and API reachability. `probeGoogleAccount(clients, services, { every })` asks Gmail profile, Calendar primary and People `me` in order (stopping at the first address unless `every`), then OAuth userinfo when none named the account, and records each failure per attempt. `resolveGoogleAccount` (`persistence/connector-account.ts`) is the managed sync's stop-at-first use: when nothing names the account it rethrows `api_not_enabled` first, then another credential error, then the first other failure (a network error stays transient), so `connector_account_changed` means a resolved account that differs from the pin. `probeGoogleApiAccess` probes every service of a setup or status run (an ungranted scope is `scope_missing` with no request) and returns `{ resolved_account, resolved_via, services, problems, fix }`; `googleApiProblem` maps `GoogleApiDisabledError` and `scope_missing` to a `GoogleApiProblem`; `googleApiAccessFix` is one Action naming every problem (`ask_user` with each enable link when an API is disabled, else the user's `gbrain google connect --reauth` command), verified by `gbrain google status --json`.
  - The clients (`google-clients.ts`) throw `GoogleApiDisabledError` (`api_not_enabled`) for a 403 with reason `accessNotConfigured`, ErrorInfo `SERVICE_DISABLED` or the disabled-API message, carrying the API, its title, the project and the enable link from the error body (ErrorInfo `activationUrl`, then the Help link, then the message; only console.cloud.google.com and console.developers.google.com links are relayed, otherwise the client id's project number builds it). A 403 for insufficient authentication scopes (`insufficientPermissions`, ErrorInfo `ACCESS_TOKEN_SCOPE_INSUFFICIENT`) is `scope_missing`, never `GoogleForbiddenError`, so a calendar read never names it `calendar_unreadable`.
  - The sweep (`google-source.ts`) records each `api_not_enabled` / `scope_missing` failure, plus an unmanaged source's ungranted services, as `api_access: { problems, at }` in source state; a service leaves it when its sweep reaches the API again, `at` changes only when the problems do, and a partial managed run publishes it with the loop recovery state.
  - `gbrain google status` (with a probe) runs `probeGoogleApiAccess` per refreshed account over its linked sources' services (every granted service when none is linked) and reports `accounts[].api_access`; a problem makes `ok: false` and exit 1. `gbrain google setup` probes every requested service (`--services`, default all) before registering anything; a problem stops it with one report (`status: api_access_blocked`, exit 2, the rendered fix and the narrower `--services` command for the reachable services).
  - When the Gmail label list itself fails, the loop exclusion log (`loops-enqueue.ts`) says the names could not be checked, never that they are not labels of the account.
  - Tests: `test/google-api-access-7073.test.ts`, `test/google-api-access-cmd-7073.serial.test.ts`, `test/google-api-access-managed-7073.test.ts` (real PGLite, and Postgres under `DATABASE_URL`).
- `src/commands/doctor/checks/google-api-access.ts` — doctor `google_api_access` (wave check, resolution operator, zero network): warns per Google source whose stored `api_access` names a service it still syncs, listing each disabled API with project and enable link, with `googleApiAccessFix` for the first source.
- `src/core/google/sender-auth.ts` — Gmail's own SPF/DKIM/DMARC verdict for a message, and the email page's `sender_auth`. `senderAuthFromHeaders(headers, fromAddress)` reads only the TOPMOST `Authentication-Results` header whose authserv-id (first token, case-insensitive, exact) is `mx.google.com`; Gmail prepends its own, so every other copy (another authserv-id, or an `mx.google.com` copy below it) is sender text and is ignored, and the first Gmail copy decides even when it cannot be read (it never falls through to a lower copy).
  - The read is strict because Gmail's copy quotes sender-chosen text (envelope sender, From domain). A property value may be a quoted-string where RFC 8601 §2.2 allows one (`value = token / quoted-string`; Gmail quotes a value holding a tspecial, e.g. `header.b="…/…"`): it reads as its unescaped text, and a `;` or `(` inside it neither splits the header nor opens a comment. A quoted string anywhere else (a method or its result, the authserv-id segment, a comment, `"…"@domain`, text glued to a quote), an unbalanced quote, a backslash outside a quoted string, an unbalanced comment, a token outside RFC 8601's `method=result` / `ptype.property=value` grammar, a repeated `spf` or `dmarc` result, a `dkim` result after `spf`/`dmarc`, or a value over 16,384 characters makes the whole header read `none`. Unknown result keywords read `none`; `spf=hardfail` and `dkim=policy` read `fail`.
  - `dkim` is `pass` when any signature passes; `dkim_domain` is that signature's `header.d`, else its `header.i` domain, lower-case and domain-shaped or null, preferring the signature aligned with DMARC's `header.from`. `dmarc` reads `pass` only when Gmail's `header.from` equals the domain of the From address GBrain parsed for the same message (`bareAddress`, which ignores an `<addr>` inside a quoted display name or comment and reads '' for a From with more than one angle-addr).
  - `threadSenderAuth(thread)` picks the thread's newest inbound message by Gmail's labels alone (no `SENT`, no `DRAFT`; a mail that only claims the owner's address is inbound) and returns `{spf, dkim, dmarc, dkim_domain, message_id, from}`; no inbound message reads every verdict `none` with `message_id` and `from` null.
  - `GmailClient.getThread` (`google-clients.ts`) sets `GmailMessageMeta.senderAuth` for every message, in full and metadata-only reads; `renderThreadPage` (`google-render.ts`) writes it as the inline-JSON frontmatter line `sender_auth:`. Pages synced before this code carry no `sender_auth` until their thread is re-synced. The field is as trustworthy as write access to the source holding the email pages.
  - Tests: `test/google-sender-auth.test.ts`.
