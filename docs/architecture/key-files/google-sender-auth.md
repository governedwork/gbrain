# Google connector: the sender's authentication verdict (key files cluster)

[Subsystem index](../KEY_FILES.md) · [Google connector + open-loop engine](google-and-loops.md) · [continued](google-and-loops-continued.md).

- `src/core/google/sender-auth.ts` — Gmail's own SPF/DKIM/DMARC verdict for a message, and the email page's `sender_auth`. `senderAuthFromHeaders(headers, fromAddress)` reads only the TOPMOST `Authentication-Results` header whose authserv-id (first token, case-insensitive, exact) is `mx.google.com`; Gmail prepends its own, so every other copy (another authserv-id, or an `mx.google.com` copy below it) is sender text and is ignored, and the first Gmail copy decides even when it cannot be read (it never falls through to a lower copy).
  - The read is strict because Gmail's copy quotes sender-chosen text (envelope sender, From domain): a quoted string, a backslash, an unbalanced comment, a token outside RFC 8601's `method=result` / `ptype.property=value` grammar, a repeated `spf` or `dmarc` result, a `dkim` result after `spf`/`dmarc`, or a value over 16,384 characters makes the whole header read `none`. Unknown result keywords read `none`; `spf=hardfail` and `dkim=policy` read `fail`.
  - `dkim` is `pass` when any signature passes; `dkim_domain` is that signature's `header.d`, else its `header.i` domain, lower-case and domain-shaped or null, preferring the signature aligned with DMARC's `header.from`. `dmarc` reads `pass` only when Gmail's `header.from` equals the domain of the From address GBrain parsed for the same message (`bareAddress`, which ignores an `<addr>` inside a quoted display name or comment and reads '' for a From with more than one angle-addr).
  - `threadSenderAuth(thread)` picks the thread's newest inbound message by Gmail's labels alone (no `SENT`, no `DRAFT`; a mail that only claims the owner's address is inbound) and returns `{spf, dkim, dmarc, dkim_domain, message_id, from}`; no inbound message reads every verdict `none` with `message_id` and `from` null.
  - `GmailClient.getThread` (`google-clients.ts`) sets `GmailMessageMeta.senderAuth` for every message, in full and metadata-only reads; `renderThreadPage` (`google-render.ts`) writes it as the inline-JSON frontmatter line `sender_auth:`. Pages synced before this code carry no `sender_auth` until their thread is re-synced. The field is as trustworthy as write access to the source holding the email pages.
  - Tests: `test/google-sender-auth.test.ts`.
